# TICKET V2-10: The Q&A pipeline

> Translated from Vietnamese on 2026-11-13; content unchanged.

## 1. Context & goal
Replace the 5–6-LLM-call pipeline with a guard + answer generation. Fix the use of models that have been shut down.

## 2. Acceptance criteria
> Criteria ending with a `D*` or `P*` code are owner decisions of 2026-10-21 (the end-to-end audit of ai-service by query type, TECH-V2-ai-service §11a). On 2026-11-08 they were merged into the right groups; content unchanged, only the "Changed 2026-10-21" prefix removed.

**Providers, limits and fallback**

- [x] An OpenAI-compatible `LLMProvider` (Gemini, Groq, Ollama/llama.cpp) chosen by env; no hard-coded model ids; at startup it calls `/models` and warns if a model was removed.
- [x] Per-provider rate limiters (RPM/TPM) always on, switching to a backup on 429 (ADR-006 §4.4). Per-user and system-wide question quotas configurable, **off by default** (owner decision 2026-10-20, FR-09, TECH-V2-ai-service §7.4). *The fallback mechanism exists in `LLMChain` with unit tests; `models.yaml` declares only one endpoint per the owner's decision (ADR-006 §4.4), so it has not run with a real backup model.*
- [x] **Fallback.** Move to the next model only before the first `delta`; errors after that → `error LLM_UNAVAILABLE`, `outcome = ERROR`, quota turn refunded. `models.yaml` has a per-model `context_max_tokens` (set for Groq after measuring on dev); switching to a model with a lower ceiling reassembles the context with that ceiling. The prompt token estimate for budgeting uses the model's own tokenizer if declared, never for chunking. (Source: P1-5.)
- [x] SSE streaming; answers in the question's language (VI/EN).
- [x] (Moved from V2-34, owner decision 2026-11-09) The Modal cost of the ~20-question quick check from the Usage page, compared with ADR-006 §4.4's $1–3 estimate, and confirmation that a workspace budget alert is set. Quote verbatim Modal's terms on multiple Starter accounts (with link and date read) and update ADR-006 §4.4 and its budget estimate if only one account ($30/month) is allowed. The endpoint's cold start takes 494 s, close to the 600 s `startup_timeout` (V2-34 §5): warm it up before runs. *Result (milestone 5): the real cost is in "Milestone 5"; the owner decided on 2026-11-09 to drop the multi-account terms part (the owner uses two Modal accounts, each with its own card; the ToS in force from May 2026 has no specific clause on this), so ADR-006 §4.4 is not changed to a single-account plan. Workspace budget alert: set by the owner on the dashboard, not checkable through the CLI.*

**Input, PII, guard and router (no LLM call)**

- [x] At most 1 generation call per question (rule-based guard, with its own check set separate from the set used to write the rules); question rewriting only with history; conversation titles generated by rules.
- [x] Rule routing (FR-13): greetings/thanks/questions about the bot (VI/EN) answered from templates, without the LLM; below the evidence threshold, refuse without calling the generator. No LLM node for intent classification (an embedding semantic-router layer is added after the rules in `V2-27`; `router.py` leaves room for it).
- [x] A "strip then judge" router: remove greeting/thanks/profanity tokens from the normalized question; if what remains is empty or below the (configurable) meaningful-token threshold, return a template by the kind of tokens removed (`outcome = TEMPLATE`); if content remains, run RAG on the stripped text. Insult-only messages get a neutral template with a hint on how to ask; profanity together with a question is still answered and records `guard_events(INPUT_FLAG)`.
- [x] **Input.** Empty questions or those longer than `SOPILOT_MAX_QUESTION_CHARS` (1000, code points after NFC) are refused, not truncated: `refusal INPUT_INVALID`, `outcome = TEMPLATE`, not counted against quotas. "Meaningful token" = a token present in the `rag.chunk_terms` of the documents the asker may read (the same `scope` CTE as §6.3) or in `qa/lexicon.yaml` (owner-reviewed); below `min_meaningful_tokens` (default 1) the "did not understand the question" template (`INPUT_INVALID`), no retrieval. The original question's vector is reused for dense only when the working text (after PII masking and stripping) equals the original question; otherwise re-embed. (Source: end-to-end audit by query type, owner decisions D2/D4/D5/D8; TECH-V2-ai-service §7.1.)
- [x] **PII.** `qa/pii.py` masks emails, Vietnamese phone numbers, and citizen ID / account numbers when preceded by a keyword (`cccd`, `cmnd`, `căn cước`, `hộ chiếu`, `stk`, `số tài khoản`…) with `[EMAIL]`, `[PHONE]`, `[ID]`, `[ACCOUNT]`, before the guard, router, rewrite, embedding and prompt; records `guard_events(INPUT_FLAG)` `rule_id = pii.*`. `messages.content` keeps the original; the gap list (`V2-13`) shows the masked version. Tests: the amount `500.000.000` is not masked; edge cases (digit strings without a keyword) are not masked. (Source: D8, P1-9.)
- [x] A VI/EN profanity dictionary in `qa/guard_rules.yaml`, matched on word boundaries (not substrings). Words that coincide with ordinary words without diacritics (e.g. the diacritic-free form colliding with "các"; "ngu" in "nguồn"; "cc"/"đm" can mean "chứng chỉ"/"định mức") are matched only on the text with diacritics; diacritic-free forms are used only for teencode with no other meaning.
- [x] Truly harmful content (threats, self-harm, harassment of a named person) has its own block-level rules: a fixed sentence, with self-harm adding a support sentence and a configurable contact; `guard_events(INPUT_BLOCK)` stores only the `rule_id`, never the original text.
- [x] `TEMPLATE` turns are not counted against quotas and do not enter the unanswered list (V2-13). The system prompt has a rule to keep a neutral tone when the question contains profanity. *The unanswered list does not exist yet; excluding `TEMPLATE` from it is checked in `V2-13`.*
- [x] The four-layer FR-13 guard: normalization + two-level VI/EN rules (block / flag), chunks wrapped in escaped data tags, an output canary token check, guard-flag logging.
- [x] Its own guard check set (80–100 questions, owner-reviewed, not overlapping `eval/provider_check/prompt_guard_cases.jsonl`) with ≥ 10 demands to reveal the system prompt, ≥ 15 VI/EN profanity messages (including teencode, no diacritics, with and without a question) and ≥ 15 valid questions that are easy to block wrongly (the diacritic collisions above): false blocks on valid questions ≤ 2%, 0 canary leaks; report the correct block rate at the rule layer. Runs in CI.

**Pipeline structure (Changed 2026-11-08, owner decision; [HANDOFF-V2-10](../../../../archive/handoffs/HANDOFF-V2-10-qa-pipeline-2026-11-08.md), TECH-V2-ai-service §7.1)**

- [x] **The pipeline is a chain of steps.** `qa/pipeline.py` runs a list of steps in TECH §7.1 order; each step receives a shared context and returns a `Decision` of `continue | template | refuse | clarify`. `clarify` is only declared in the type; no step emits it yet. The `OUT_OF_SCOPE` hook for `V2-27` sits in the refusal step after the gate. Unit tests: step order, a `Decision` stops the chain at the right place, LLM calls ≤ 2.
- [x] **`QueryFrame`.** `qa/query_frame.py` (a pure function) is built once after the PII step: language, document codes (using `qa/doc_code.py`), dates and amounts, follow-up signals, comparison/multi-part signals (keywords in YAML or ≥ 2 document codes), the count of meaningful tokens. The router, retrieval and prompt read from the `QueryFrame` and do not re-detect. The comparison signal is only recorded in `messages.route.signals.comparison`, with no branching.
- [x] **A loose threshold gate; the LLM refuses by itself.** Keep the placeholder threshold in `config/models.yaml` (`hybrid: 0.45`), not lowered further, no new value from the RQ3 numbers. A question that passes the gate but whose answer opens with the fixed sentence → `GENERATOR_NOT_FOUND`. Always record `gate_score`, `threshold` and the refusal kind in `messages.route`; the reasons are in TECH §7.1.

**Rewriting and follow-ups**

- [x] **Rewriting and follow-ups.** Record `messages.rewrite_status`. A failed rewrite of a question with follow-up signals (`qa/followup_rules.yaml`: "đó", "này", "vậy còn", "thế còn", "it", "that", "what about", or fewer than `SOPILOT_FOLLOWUP_MAX_TOKENS` tokens) → a template asking for the full question, no retrieval, `route.layer = 'followup_rule'`; without follow-up signals use the original question. The generation prompt gets the rewritten question plus the original, and **not** the conversation history; tested with a fake provider that records the prompt. (Source: D5.)

**Retrieval and context assembly**

- [x] Small-to-big context assembly in `retrieval/context.py` (pure functions, importable by `eval/`): the same-`section_path` group of the hit chunk, groups ≤ `section_max_tokens` taken whole, larger ones ±1 plus the section's lead paragraph for `PROCEDURE_STEP`/`TABLE`, adjacent windows merged, a `context.max_tokens` ceiling; the expanded-chunk query goes through the §6.1 access filter; `[n]` points to a source and the citation span covers only hit chunks; `messages.context_sources` recorded. `context.expand = false` keeps the hit-chunks-only behaviour. (Source: TECH-V2-ai-service §6.4a.)
- [x] A context-assembly ablation on a fixed harness subset: `expand` on/off, reporting evidence coverage (the share of gold spans inside the context, no LLM needed, run on the whole test set), faithfulness, citation precision, prompt tokens; separately for condition/exception questions and multi-passage questions. `expand` stays `true` by default unless the measurements show it is worse.
- [x] Rerank and the LLM context receive only access-filtered candidates; answer/retrieval caches (if any) have keys including `workspace_id`, `wrole`, `wdept`.

**Prompt**

- [x] **Prompt.** `<source>` has `code`, `rev`, `effective` from the source `version_id`'s `extracted_documents.extracted_meta` (`rag` tables, no reading of `core`; missing attributes omitted; escaped), without changing `index_text`; the system prompt has a "Today is {date}" line in `SOPILOT_TIMEZONE`; a rule for situational questions (list the conditions, say which are met or lack information, answer in the form "if … then …"); `prompt_version` changed. (Source: D3, P0-5, P1-4.)

**Citations, outcome and refusal**

- [x] Every `[n]` maps to `document_id`, `page` and a passage; unmappable citations are removed.
- [x] **Outcome.** Fill `messages.refusal_reason` (`NO_EVIDENCE`, `GENERATOR_NOT_FOUND`, `OUT_OF_SCOPE`, `INPUT_INVALID`, TECH-V2-ai-service §3.4). The system prompt requires the fixed opening sentence when the sources lack the information; deterministic string matching (VI/EN) → `outcome = REFUSED_NO_EVIDENCE`, `GENERATOR_NOT_FOUND`, no citations stored. An `ANSWERED` message without any valid `[n]` records `checks.citationCount = 0`. `qa/pipeline.py` provides the `OUT_OF_SCOPE` hook for `V2-27`'s router (only after the gate refuses, without closest documents). The item "Below the evidence threshold… recorded in the unanswered list" below applies only to `NO_EVIDENCE` and `GENERATOR_NOT_FOUND`. (Source: D2.) *The hook exists; emitting `OUT_OF_SCOPE` is `V2-27`'s job.*
- [x] Below the evidence threshold: answer "not found" with the closest documents, `refusal_reason = NO_EVIDENCE`, recorded in the unanswered list. Answer-level RQ3 reports the **gate refusal** (`NO_EVIDENCE`) separately from the **LLM's own refusal** (`GENERATOR_NOT_FOUND`) ([RESEARCH-03](../../../../research/research-03-methods-and-models.md) §7.2). *"Recorded in the unanswered list" moved to `V2-13` (owner decision 2026-11-09), because the list belongs to that ticket.*
- [x] **Number and date check.** `qa/checks.py` (pure functions) compares numbers, dates and amounts in the final answer with the sources' content; values absent from the sources → `done.warnings` `NUMBER_NOT_IN_SOURCES` and `checks.numberWarnings`. Flag only, never edit the text. Measure the correlation with the subset's faithfulness labels. (Source: P1-3.)
- [x] `messages.route`, `rewrite_status`, `checks` filled for every question (the columns are in `V2-09`'s migration). End-to-end TTFT is measured in `V2-16`. (Source: P0-8, P1-7.)

**Conversations**

- [x] Only the creator can see a conversation (filtered by user and workspace). On reopening, answers citing documents no longer readable are hidden with a reason (ADR-007 §4.5).
- [x] (Moved from V2-14) Extend the tenant-isolation suite: Q&A and the conversation API with ≥ 3 workspaces holding their own "secret strings" never return another workspace's string, citations or conversations (`404` for ids outside the workspace); runs in `tenant-isolation.yml`. *Milestone 3 (2026-11-09): `tests/integration/test_qa_isolation.py` (4 tests) runs in the `ai-service` job of `tenant-isolation.yml` since commit `75da176`; CI run `42555955927` (develop, 2026-11-09) 4/4 pass.*

**C. `eval/sopilot_eval/answers.py`, command `answers`**: citation precision, the refusal rate split into `NO_EVIDENCE` / `GENERATOR_NOT_FOUND` (for answerable and unanswerable questions), faithfulness on a hash-fixed subset (`--subset-size`, `--subset-seed`) with a `temperature = 0` judge, and the correlation of the `NUMBER_NOT_IN_SOURCES` flag with faithfulness, all for `expand` on/off.
